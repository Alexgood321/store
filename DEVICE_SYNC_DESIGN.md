# My Store Manager: архитектура обновлений и учёта устройств

## Задача

Обновления плагинов не должны требовать ручной замены URL магазина. Нужно различать
публикацию версии на GitHub, запись нового URL в память Lampa, успешную загрузку
адреса Lampa и **подтверждённую работу версии**. Последнее нельзя доказывать
только наличием URL: Lampa может выполнить код из собственного кэша.

## Источники истины

1. **GitHub Actions** раз в 5 минут проверяет разрешённые источники и формирует
   `live_catalog.json` (`sha`, `version`, `published_at`, `link`).
   Участие клиента для этого не требуется.
2. **Локальный менеджер Lampa** получает каталог при открытии/по таймеру,
   записывает установленный URL, определяемую из JS версию, флаг включения и
   наличие URL в `Lampa.Plugins.loaded()`; сохраняет время установки, смены
   URL, проверки и наблюдения загрузки.
3. **Отдельный реестр устройств** нужен только для общей панели Mac/iPhone/
   iPad/Android TV. Статический GitHub-репозиторий этого не умеет. Бесплатный
   CUB не предоставляет необходимой синхронизации пользовательских storage keys
   в рассмотренной реализации Lampa.

## Статусы (не смешивать)

- `available`: версия опубликована на GitHub (дата `published_at`).
- `configured`: в локальном `plugins` записан URL новой версии (дата `applied_at`).
- `url_loaded`: Lampa сообщила URL среди `Plugins.loaded()` в текущем сеансе
  (дата `observed_at`); это **не доказательство исполнения именно новой версии**
  при fallback на кэш.
- `runtime_verified`: плагин собственным API/Manifest сообщает version/build/sha.
  Если такого API нет, статус должен быть `unknown`, а не «успешно обновлён».
- `pending_restart`: сконфигурирован новый URL, но текущий запуск не подтвердил
  его загрузку.
- `failed`: адрес не загрузился или проверка целостности/доступности не прошла.

Отдельно хранить `checked_at`, `applied_at`, `observed_at`, `verified_at`
и `last_seen` в UTC, отображать в локальном времени устройства.

## Автоматическое обновление

- Собственные SURS Pro, Home Categories Pro, NUM Series Pro и HDREZKA:
  можно разрешить автоматическую смену URL на проверенный SHA. При
  изменениях сохранять backup/журнал перед записью в storage.
- Сторонние плагины: без автоматической замены URL по умолчанию.
- Во время просмотра **не перезагружать** приложение. Изменённый URL начнёт
  действовать при следующем обычном запуске; для немедленного применения
  пользователь выбирает «Обновить мои и перезапустить».
- Если несколько URL меняются одновременно, сохранять один атомарный
  снимок до изменения и уметь откатить всю группу.
- В будущем: при выпуске нового loader/runtime сначала проверка совместимости
  на одном устройстве, затем остальные устройства; не проводить горячую
  замену исполняемого JS в текущем сеансе.

## Кнопки локального менеджера

- **Проверить актуальные версии**: принудительно прочитать `live_catalog.json`
  с nonce. Не очищать localStorage, IndexedDB, CUB и историю.
- **Обновить мои и перезапустить**: подтвердить, сохранить backup, заменить
  URL собственных плагинов на проверенные ссылки, вызвать
  `window.location.reload()` после сохранения.
- **Перезапустить без очистки кэша**: то же `location.reload()`,
  без удаления каких-либо пользовательских данных.
- **Журнал изменений**: локальные события, время, старый и новый URL.
- **Откат**: восстановить предыдущие URL и после подтверждения перезапустить.

## Будущий защищённый реестр нескольких устройств

Отдельный сервис на VPS под HTTPS, SQLite на малое число устройств. Никакие
GitHub-токены или администраторские ключи нельзя встраивать в JS-плагин.

Предлагаемый API:

- `POST /v1/pair`: одноразовое сопряжение устройства коротким токеном с TTL
  10 минут. Выдаёт **персональный** токен только для записи своих данных.
- `PUT /v1/device/report`: статус текущего устройства с device token
  (`device_id` определяется сервером по токену).
- `GET /v1/devices`: список устройств только с отдельным токеном чтения.
- `GET /v1/devices/{id}/history`: журнал и статусы конкретного устройства.
- `POST /v1/devices/{id}/commands`: только постановка разрешённой команды
  (например `check`, `stage_update`), без произвольного JS/eval.

Модель отчёта:
```json
{
  "schema": 1,
  "device_id": "random-local-id",
  "device_name": "Mac mini",
  "observed_at": "2026-11-04T11:00:00Z",
  "store_version": "2.4.0",
  "plugins": [
    {
      "id": "SURS Pro",
      "configured_version": "3.8.2",
      "configured_sha": "02f879c9...",
      "runtime_version": null,
      "runtime_verified": false,
      "url_loaded": true,
      "pending_restart": false,
      "applied_at": null
    }
  ]
}
```

Все значения в примере условные, не реальная телеметрия пользователя.
Передавать только разрешённые имена плагинов, безопасные хэши/пути и версии.
Никогда не отправлять query-параметры подписок, VPN URL, токены и пользовательские
настройки. Ограничить размер пакета, частоту запросов и хранение журнала.
При недоступности сервера Lampa продолжает работать локально; накопленные
изменения отправляются после восстановления связи.

Публикация `published_at` и локальная панель не зависят от сервера. Реальную
межустройственную синхронизацию нельзя считать работающей, пока backend не
развёрнут и устройства не сопряжены.
