# My Store 3.6.1 — централизованное обновление Lampa

## Постоянная ссылка

`https://cdn.jsdelivr.net/gh/Alexgood321/store@main/my_store_loader.js`

Это единственная установочная ссылка. Не добавляйте отдельные копии My Store. Прежние
`my_store_live.js`, `my_store.js`, `store.js` и `alex_store.js`
перенаправлены на идентичный загрузчик.

## Источники версий и реальная нагрузка

* **My Store на устройствах:** читает только публичный
  `https://raw.githubusercontent.com/Alexgood321/store/main/live_catalog.json`
  с параметром для обхода кэша и резервом jsDelivr. GitHub REST API не
  вызывается ни загрузчиком, ни ядром. 0 API-вызовов на устройство, независимо
  от количества Mac, iPhone, iPad или TV.
* **Центральный GitHub Action:** использует `GITHUB_TOKEN` (не хранится в
  клиентах), `sync_sources.json` и `scripts/sync_catalog.py` для проверки
  коммитов отслеживаемых расширений (запросы по независимым файлам
  обрабатываются с ограниченной параллельностью).
* **Доставка новых выпусков:** `repository_dispatch` из рабочих репозиториев
  `Alexgood321/lampa-plugins` и `Alexgood321/lampa-hdrezka`. Резервная
  проверка по расписанию — каждые 5 минут, если GitHub действительно исполняет
  запланированные задания. Дополнительно доступен ручной запуск workflow.
* **Каталог:** `live_catalog.json` содержит версию, полный SHA, ссылку и
  `published_at` каждого плагина, историю предыдущих SHA и версий
  в `meta.history`, а также `meta.last_checked_at`.
  Последнее обновляется максимум раз в 30 минут, **только если критические
  источники успешно проверены**. Если Action не выполняется, время устареет
  и Lampa покажет предупреждение, а не ложный статус «актуально».
* Установленные плагины обновляются **только при включённом пользователем
  автообновлении**; сохранённая ссылка заменяется на проверенный коммит,
  и запись попадает в журнал. Сам JS начнёт работать при следующем запуске
  Lampa. Имеется откат.

## Однократная активация немедленных событий публикации

Нужен отдельный **fine-grained personal access token** GitHub:
Repository access → Only selected repositories → **Alexgood321/store**;
Repository permissions → **Contents: Read and write**. Именно такой доступ
требует GitHub REST `POST /repos/{owner}/{repo}/dispatches`.

Поместить этот токен в **Actions secret** с именем `STORE_DISPATCH_TOKEN`
в каждом из двух исходных репозиториев:

* `Alexgood321/lampa-plugins` → Settings → Secrets and variables → Actions
* `Alexgood321/lampa-hdrezka` → Settings → Secrets and variables → Actions

Файл `.github/workflows/notify-store.yml` уже установлен в обоих.
При публикации JS отправляется событие `lampa-plugin-updated`, которое
запускает `Alexgood321/store/.github/workflows/sync_catalog.yml`.
Если секрет отсутствует, workflow выводит предупреждение; успешный зелёный
значок самого workflow **не означает, что событие доставлено**.
**Никогда не добавляйте PAT в JS клиента, каталог или коммит.**

Необходимые GitHub workflow permissions в репозитории магазина:
`contents: write` для коммита `live_catalog.json`. Сохраняется
резервное расписание и `workflow_dispatch`.

## Обновление ядра самого My Store

`my_store_loader.js` каждый запуск читает `meta.tracked["My Store"]` из
того же каталога, загружает `my_store_runtime.js` по закреплённому SHA,
ждёт подтверждения инициализации и сохраняет последнюю рабочую сборку.
Если каталог недоступен, загрузчик проверяет `my_store_release.json` и
последнюю рабочую сборку. Если центральный каталог устарел, интерфейс
не утверждает, что установлена новейшая версия.

Когда меняется `my_store_runtime.js`, workflow обновляет метаданные.
`my_store_release.json` остаётся резервным указателем, а не альтернативой
основному каталогу.

## Кнопка «Обновить всё» в шапке Lampa (My Store 3.4.0)

Кнопка **выключена по умолчанию**. Включение и выключение выполняется
на самом устройстве через «Мои плагины → Управление обновлениями →
Кнопка обновления в шапке». Выбор сохраняется в
`alexgood321_store_header_batch_v1` и не меняет глобальные настройки Lampa.
Кнопка добавляется штатным API `Lampa.Head.addIcon()`; выключение сразу
удаляет её с экрана. К существующей кнопке перезагрузки Lampa отношения
не имеет.

Одно нажатие перечитывает основной `live_catalog.json` с cache-busting
параметром, без GitHub REST API. По всей коллекции активных отслеживаемых
плагинов выбираются **только подтверждённые более новые семантические версии**,
для которых имеется отличающаяся ссылка. Неопределённые версии,
потенциальные откаты, выключенные плагины и неактуальный/резервный
каталог пропускаются. Обновление My Store как ядра также распознаётся по
разнице SHA и применяется через загрузчик при перезапуске.

Подтверждённые ссылки заменяются **одним сохранением**, резервная копия
всей группы доступна через «Данные этого устройства и журнал →
Откатить последнее групповое обновление». Статус в шапке показывает
счётчик доступных обновлений или знак перезапуска после применения.
Если плеер Lampa открыт, воспроизведение не прерывается: потребуется
перезапуск позже. В остальных случаях после успешного применения
выполняется перезапуск Lampa без очистки кэша. Если её сборка не
предоставляет `window.location.reload`, пользователю показывается
сообщение о ручном перезапуске.

Фоновая проверка планируется каждые 5 минут и не зависит
от наличия кнопки, но пропускается при воспроизведении или
свёрнутом приложении, чтобы не мешать просмотру. Автоматическое обновление ссылок остаётся
отдельной настройкой: включать кнопку можно без его включения.

## Проверка после настройки

1. Опубликовать новую версию `rezka.js` или выполнить GitHub
   Actions → Notify Lampa My Store of plugin releases → Run workflow.
2. Убедиться, что в `Alexgood321/store` появился запуск
   **Sync Lampa plugin catalog** с событием **repository_dispatch** и
   успешным результатом.
3. Убедиться, что `live_catalog.json` обновил SHA, версию и время.
4. В Lampa → Мои плагины → Проверить обновления. Убедиться, что
   уведомление показывает корректную версию без REST-запросов.
5. При включённом автообновлении проверить новую ссылку в «Установленные
   в память», запись в журнале; после перезапуска — работающую версию.

Если секрет не настроен или GitHub выключил расписание в форке, нельзя
гарантировать своевременную публикацию новых версий в каталоге. Для
проверки можно использовать Run workflow в репозитории магазина.

Проверка по расписанию может запускаться с задержкой, это не точный
пятиминутный SLA. Сама проверка с Lampa через 5 минут не запускает
GitHub Actions, она только читает уже опубликованный каталог.
